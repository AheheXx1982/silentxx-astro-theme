# SilentXx SmartToc — 智能文章目录组件

> 由 [SilentXx](https://silentxx.com) 设计与开源 · 为 Astro + React 站点提供自适应文章目录

[English](./README.md) · [npm](https://www.npmjs.com/package/silentxx-smart-toc)

一个"聪明"的目录组件：无论文章长什么样，它都能找到最合适的导航方案——真正的标题树、AI 语义章节、伪标题识别、段落导航，或者干脆显示"暂无目录"。**全程不需要改写文章。**

---

## 为什么需要它

大量从公众号 / 论坛 / 旧 CMS 迁移过来的存量文章没有 Markdown 标题结构（没有 `##`/`###`）。传统 TOC 组件对它们只会显示"暂无目录"，长文读者失去导航。

SilentXx SmartToc 用 **5 级降级链**解决——永远为当前内容找到最好的导航：

```plain
标题树  →  AI 语义章节  →  伪标题识别  →  段落导航  →  "暂无目录"
```

## 功能特性

- 🤖 **AI 语义章节**：无标题文章由 AI 把相邻段落按语义聚类（讲同一意思的段落 = 一章），生成精炼小标题。输出**只进左侧目录树——文章内容一字不改**。
- 🌲 **标题树**：层级缩进 + 自动编号（1. / 1.1 / 1.2……），默认全展开，滚动手风琴定位。
- ✨ **伪标题识别**：自动识别作者用普通短句写的小标题（5-30 字独立行，如「活在当下的真谛」）。
- 📄 **段落导航**：最终兜底——每段一个锚点，编号 + 段落开头 18 字预览。
- 🧭 **滚动高亮**：随阅读位置自动高亮当前目录项；点击平滑滚动。
- 🆔 **稳定中文锚点**：标题生成真实锚点 id（如 `#为什么剩下`），替代 `heading-0` 式弱 id。
- 🧹 **智能过滤**：纯图片段、引用块、列表、表格自动排除出导航。
- 📦 **零内容改动**：纯客户端组件，不碰 Markdown 源文件与渲染链。

## 安装

```bash
npm install silentxx-smart-toc
```

需要 Astro 项目已集成 React：

```bash
npx astro add react
```

## 快速开始

把组件放进你的项目（如 `src/components/layout/SilentXxSmartToc.tsx`），在侧边栏使用：

```astro
---
import { SilentXxSmartToc } from '@components/layout/SilentXxSmartToc';
---

<SilentXxSmartToc client:load defaultExpanded />
```

组件会自动扫描页面上的 `<article>` 元素收集标题和段落——正文用 `<article>` 包裹即可，无需其他配置。

## Props

| 参数              | 类型      | 默认    | 说明                                                                    |
| ----------------- | --------- | ------- | ----------------------------------------------------------------------- |
| `defaultExpanded` | `boolean` | `false` | 标题树模式下是否默认展开所有子标题（建议 `true`）                       |
| `tocDataUrl`      | `string`  | 自动    | AI 目录数据 JSON 地址，默认 `/toc-data/<slug>.json`（slug 从 URL 提取） |

## AI 目录数据（可选，但很强）

无标题文章只要提供构建时生成的 JSON 文件（放 `public/toc-data/<slug>.json`），组件就会渲染成语义章节。**文章本身完全不动。**

```json
{
  "slug": "my-article",
  "generated": "2026-08-30",
  "sections": [{ "title": "章节标题", "anchor": "该章节起始段落的开头文字" }]
}
```

- `anchor` 按段落 `textContent` 前缀匹配，用于定位章节起始段落。
- 文件缺失时组件自动降级：伪标题识别 → 段落导航。

### 如何生成 AI 目录数据

在构建流程里加一个 `generate-toc` 步骤（任意支持 JSON 输出的 LLM 均可）。输入文章正文，提示模型：

1. 把相邻段落按主题聚类——讲同一件事的段落归为一章；
2. 每章生成精炼标题（6-20 字）；
3. 输出 `{ "sections": [{ "title", "anchor" }] }`，`anchor` 取章节首段开头的 4-12 字（原文逐字复制）。

写 JSON 前程序化校验：每个 anchor 必须能前缀匹配到真实段落。

## Markdown 规范化工具（配套）

`scripts/md-normalize.py` —— 针对**有小标题但格式不规范**的文章：

- 检测独立成段的短行（5-30 字）是否为伪标题；
- 转为标准 `##` 标题（修复 `✨ 1.` 编号结构、软换行、中文引号等问题）；
- 排除误判：冒号结尾的引导句（「大宝剑是什么：」）、句号/感叹号结尾的陈述句、图片/引用/列表段落；
- 转换前自动备份每个文件。

跑一次即可永久规范化存量文章——之后目录直接走标题树。

## 架构

```plain
┌─────────────────────────────────────────────────────────┐
│  SilentXxSmartToc (React, client:load)                  │
│                                                         │
│  1. 扫描 <article> 里的 h2-h6                           │
│     ├─ ≥2 个标题 ────────────────► 标题树模式            │
│     └─ 否则 ──────────────────────────────────────┐     │
│  2. fetch /toc-data/<slug>.json                    │     │
│     ├─ 有有效章节 ───────────────► AI 章节模式       │     │
│     └─ 缺失/无效 ─────────────────────────────┐    │     │
│  3. 伪标题识别（5-30字独立行，≥3个）            │    │     │
│     ├─ 找到 ────────────────► 伪标题模式        │    │     │
│     └─ 没有 ──────────────────────────────┐    │    │     │
│  4. 段落导航（≥5 个有效段落）               │    │    │     │
│     ├─ 足够 ────────────────► 段落导航模式   │    │    │     │
│     └─ 太短 ────────────────► "暂无目录"    │    │    │     │
│                                        └────┴────┘    │
└─────────────────────────────────────────────────────────┘
```

所有模式都支持滚动高亮与点击平滑跳转。

## 样式说明

组件使用 **Tailwind CSS 工具类 + CSS 变量**（`--primary`、`--muted-foreground` 等），与 SilentXx 主题一致（浅/深色自适应）。在未定制主题的项目中，可覆盖类名或提供对应 CSS 变量；无样式（headless）版本规划中。

## 常见问题

**Q：AI 目录数据会修改我的文章吗？**
A：不会。目录数据是独立的 JSON 文件，组件只在侧边栏渲染。文章保持逐字节不变。

**Q：我不想生成 AI 数据。**
A：没问题——组件自动降级到伪标题识别、再降级到段落导航，全部自动化。

**Q：我的站点不用 Tailwind。**
A：类名照常输出但需要你定义 CSS 变量才有样式。可覆盖 `.toc-container` 样式，或等 headless 版本。

**Q：URL 里带中文锚点？**
A：故意的——稳定、可读、合法的 HTML5 id（如 `#为什么剩下`）。
